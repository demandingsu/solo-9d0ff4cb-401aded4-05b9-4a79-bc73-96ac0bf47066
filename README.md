# 园区月度电量试算工具

把园区月度电量 XLSX 上传到网页，选择**本楼栋工作表**和**园区总计单元格**，
导出一份试算工作簿：

- 本楼栋工作表完整保留（布局、样式、合并单元格、行高列宽），读数可直接修改；
- 其余楼栋/工作表的底数不进表，只折算成**一个汇总常数**（`试算汇总!A1`）；
- 园区总计（`试算汇总!B1`）= 汇总常数 + 本楼栋相关读数，含区域与跨表引用，
  符号（含“先计入再扣除”）原样保留；
- 修改本楼栋读数后，试算表的园区总计与「在原表上做同样修改后重算」结果一致；
- 工作簿写入 `fullCalcOnLoad`，用 Excel/WPS 打开即自动重算。

公式支持范围（超出即报错，**指出单元格并停止导出**，HTTP 422）：

- 同一工作簿内的单元格引用、区域引用（含跨工作表，支持 `'表 名'!A1`、`$` 绝对标记）；
- 函数仅 `SUM`；
- 运算符仅加法 `+`、减法 `-`（含一元正负号与括号）；
- 底数必须是整数（浮点存储但值为整数的可接受，空单元格按 0，数字文本按其数值）；
- 跨工作簿引用 `[外部.xlsx]Sheet1!A1`、乘除、乘幂、百分号、比较、文本连接、
  其他函数等一律拒绝；循环引用给出完整单元格链路。

## 目录结构

```
app/
  formula.py    公式词法/语法分析，AST 节点（白名单式语法）
  analyzer.py   依赖展开、成环检测、本楼栋/外部底数拆分、整表校验
  builder.py    试算工作簿生成（两表：本楼栋 + 试算汇总）
  server.py     Flask 路由：/ 上传、/upload 选表、/export 导出
  templates/    上传页、选择页、错误页
tests/
  test_pipeline.py  18 个自测（含跨表“同一读数先计入再扣除”）
data/           运行时上传目录（compose 挂载持久化，自动创建）
```

## 实现要点

1. **白名单公式解析**（`formula.py`）：自写词法器 + 递归下降解析器，
   只产出 Number / Ref / SUM / BinOp(+,-) / UnaryOp 节点；任何白名单外的
   token（`* / ^ % & = < >`、其他函数名、`[ ]`、字符串、小数等）直接报错。
2. **依赖展开与成环检测**（`analyzer.py`）：从总计单元格沿引用递归展开，
   维护访问栈，重复入栈即报出 `A!x -> B!y -> A!x` 形式的环链。
3. **本楼栋 / 外部拆分**：
   - 本楼栋工作表的公式内联到原始读数单元格（可编辑、可联动）；
   - 外部工作表的公式整体按当前底数求值折成整数，**但其中对本楼栋工作表的
     引用仍保留为可联动引用**，不会被错误折进常数；
   - 所有外部整数合并成**一个**汇总常数；
   - 带符号叶子项（`Term(sign, ref|number)`）保留每一处 +/-，因此同一读数
     在区域里被 `+SUM(...)` 计入、又被单点 `-B3` 扣除时，符号不丢。
4. **试算工作簿**（`builder.py`）：只输出两张表；楼内公式重写为
   “本楼栋引用 + 内联常数”的加和；合并单元格只写左上角（openpyxl 的
   MergedCell 只读）；楼栋表名与保留名 `试算汇总` 冲突时自动改名并同步
   修正全部公式引用。
5. **网页流程**（`server.py`）：上传文件按 UUID 落盘（防路径穿越），
   20MB 上限；选择页填楼栋表与总计单元格（支持 `表!单元格` 与裸坐标）；
   导出失败渲染错误页并给出问题单元格，不产生下载。

## 用 Docker Compose 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

镜像基于 `python:3.11-slim`，gunicorn 双 worker，上传目录挂载到 `./data`。

本地裸机调试（Python 3.11）：

```bash
pip install -r requirements.txt
PYTHONPATH=. python -m flask --app app.server run --debug
```

## 自测

```bash
PYTHONPATH=. python -m unittest discover -s tests -v
```

## 实测记录（交付前核对）

环境无 Docker/无系统 pip，依赖装在独立目录用 `PYTHONPATH` 引用
（openpyxl 3.1.5、Flask 3.1.3、gunicorn 23.0.0），不影响交付物。

- `unittest`：**18/18 通过**，覆盖
  - 跨表“同一读数先计入再扣除”：`='1号楼'!B4(=SUM(B2:B3)) + '2号楼'!B4 - '1号楼'!B3`，
    外部常数 280，导出总计 `=试算汇总!$A$1+SUM('1号楼'!B2:B3)-'1号楼'!B3`；
    B2 改 150、B3 改 55 后独立复算 = 430，与原表同改重算 430 一致；
    B3 再改 999，区域 +999 与单点 -999 抵消，总计仍 430；
  - 外部区域 `SUM('2号楼'!B2:B4)` 折成单一常数，输出表不含 2 号楼；
  - 外部公式反向引用本楼栋读数时，该读数保持可联动；
  - 不支持函数（ROUND/IF/AVERAGE/MAX）、乘除等运算符、跨簿引用、小数、
    非整数底数、循环引用均被拒绝且报错含具体单元格；
  - 合并单元格/样式/列宽保留；楼栋表与汇总表同名时引用重映射；
  - Flask 测试客户端的上传→选择→导出全流程及 422 错误页。
- gunicorn 实跑（本机 8011 端口）+ curl 全流程：上传 200、导出 200，
  下载文件经 openpyxl 复核为两张表、常数 280、公式与预期一致；
  ROUND 公式与成环文件分别返回 422 且页面指明 `园区汇总!B2`、
  `1号楼!B2 -> 1号楼!B3 -> 1号楼!B2`。
- 下载文件解包确认 `xl/workbook.xml` 含 `fullCalcOnLoad="1"`。
- 公式解析边界探针：`*/^%&=<>;`、`A1:`、`1E3`、`TRUE()` 等均被拒绝；
  `=-A1`、`=A1--B2`、括号、多参数 SUM、引号表名等正常接受。

## 未完成项 / 已知限制

1. 本沙箱**未安装 Docker**，`docker compose up --build` 未在本机实际执行；
   Dockerfile/compose 仅做了语法与配置核对，需在有 Docker 的环境验证一次。
2. 未用真实 Excel/WPS 打开文件验证重算（环境无 Office）；已通过写入
   `fullCalcOnLoad` 并用独立求值器交叉核对公式语义。
3. 仅支持 `.xlsx`；旧版 `.xls`、含 VBA 的 `.xlsm` 未支持。
4. 底数限定整数；千分位文本、货币符号文本等不会被识别为数字（会报“不是整数”）。
5. 命名区域（Defined Name）、结构化表引用、3D 引用（`Sheet1:Sheet3!A1`）
   不在白名单内，遇到会按不支持处理。
6. 上传文件以 UUID 保存在 `data/`，目前没有定时清理任务，需运维侧定期清理。
7. 未做登录鉴权，部署时应放在内网或前置网关后。
